# dsh-paper-insight v0.2.4 设计规范

状态：架构方案已确认；本规范待用户复核。本文不表示功能已实现或版本已发布。

## 1. 目标与范围

依据用户提供的 `dsh-paper-insight-v0.2.4-roadmap.md`，在现有 Cordis 插件上交付章节覆盖、结论审查、产品机会卡片、预算控制及 GitHub/npm 同包发布。复用 Harness 的模型路由、工具、工作区权限与网页服务，不修改 Harness 核心。

本版本不包含 OCR、原文报告双栏、跨论文知识图谱和后台调度。现有 27 个工具的名称和既有参数调用方式保持兼容；新增能力采用可选参数及必要的新工具，不以“总数仍为 27”限制扩展。

## 2. 现状与模块边界

`lib/content.js` 负责提取、分块和均匀抽样；`lib/analysis.js` 负责证据与模块生成；`lib/model.js` 复用 `ctx.llm.prepareCall` 并记录调用；`lib/workflow.js` 保存阶段和检查点；`lib/storage.js` 管理归档；`index.js` 定义工具；`lib/web.js` 将同一工具接入工作台。

新增章节选择、证据复核、产品机会和预算的独立模块，避免将规则继续堆入工作流。服务层组合能力，网页和自然语言工具共享校验及权限边界。

## 3. 章节识别、抽样和补充研究

- 识别 abstract、introduction、related-work、methods、experiments、results、limitations、conclusion、references 和 unknown。依据显式标题识别，不用关键词出现一次就推断整段所属章节；无法确认时记录 unknown。
- 保留来源定位与原始片段稳定标识。章节分类作为附加元数据，不能使旧 `P1.F1` 引用指向其他文字。旧检查点按原分块参数和文本哈希恢复；重建结果不一致时不得复用对应证据。
- 新任务优先选择方法、实验、结果和局限，模块选择影响优先级；预算足够时为其他已识别正文章节保留最低覆盖，再按确定顺序补齐。片段上限不足以覆盖所有章节时明确列出缺口。参考文献不优先于正文。
- 分开记录可用片段、选中片段和成功提取证据的片段。覆盖率以实际处理成功的片段为准；章名未识别不代表该章不存在，PDF 页数限制不进入“已读取全文”的表述。
- UI 显示已处理/总片段、各章节覆盖与 unknown，并说明这是文本处理覆盖，不代表理解正确率。
- 补充研究接受已有 key/runId 和待补充章节，复用保存的正文及匹配哈希的证据，处理新增片段后重新生成所选分析模块；生成新 runId，记录 parentRunId，旧报告不覆盖。无可补充内容时返回明确说明，不启动无意义模型调用。
- 保留 abstract-only、partial-text、extracted-text；完整提取也明确标注公式、图表和语义理解未经全面验证。

## 4. 结论审查与人工记录

每条结论保留稳定的运行内 ID、原始类型、原始文本、引用和置信度。类型保持论文事实、文献事实、推断、产品设想及证据不足的区别。

第一层为确定性校验：引用存在、短引与原文一致、事实所需来源类型合法，以及明显的数字、单位或研究条件缺失。规则只发现矛盾和缺口，不声称证明语义一致。

第二层只对性能、成本、安全和可行性等高风险断言进行有界模型复核。输入为原结论、所引短引及可用上下文；输出逐项检查研究对象、数据集、对照组、指标/单位和前提，并给出理由。未知字段必须保持未知。审核调用及修复也计入统一预算，结果单独保存并可恢复。

审查状态为“有直接依据 / 需人工核查 / 证据不足”，显示依据及审查方式。“有直接依据”表示材料中存在直接支持且未发现指定维度冲突，并非真实性或因果性的保证。推断和产品设想不得因二次模型肯定而升级成事实；未审核的高风险事实默认需人工核查。无效引用拒绝接收；复核失败保留未审核状态和原因。

人工记录采用独立追加修订记录，包含结论 ID、报告内容哈希、确认/质疑/待复核状态、备注和时间；仅反映当前本地用户的操作，不伪造身份。并发编辑使用 revision 冲突检查。人工意见不改写模型原文和原始审查结果，报告换版本后不自动继承确认。

## 5. 产品机会卡片与导出

features、products、sandbox、decision 可输出结构化机会，每条包含：名称、用户、场景、痛点、论文机制、技术能力、产品能力、功能、证据 ID、假设、价值、可行性、成本、风险、验证指标、依赖、用户流程、验收标准、PoC 步骤、停止条件和推荐状态。

价值、可行性、成本和证据充分性分项呈现，不伪造综合分数。支持采用/待验证/不建议采用；不适用时允许空机会列表及具体理由。缺少可引用证据的构想必须标注假设，收益不得写成已验证数值。

卡片 ID 绑定运行与内容；人工优先级和备注使用独立修订记录，不覆盖模型建议。知识聚合保留 key/runId/卡片 ID，不能将不同论文条件混成共同验证结果。

按卡片导出 PRD/PoC Markdown，明确为草稿，携带来源、假设、未决项、指标和停止条件；导出不额外调用模型。保留既有 product-ideas.md 和 poc.md，并增加结构化卡片 JSON 和可读草稿。

## 6. 预算、模式与运行统计

配置及单次分析可选参数增加最大调用次数、可选总 Token 预算和研究模式。初始默认最大调用次数 64，总 Token 限制默认不启用；手工模块优先于模式预设。快速阅读默认 paper、beginner；深度研究默认 paper、principles、research、decision；产品研究默认 paper、sandbox、features、products、experience、decision。

所有提取、生成、修复、审查及重试在实际发起前占用一次调用额度。失败调用也计数；不允许通过修复或恢复绕过。检查点持久化消耗，继续同一研究链时累计预算；用户提高总预算后才能继续。独立重新分析可创建新预算，但 UI 明确显示为新研究运行。

Token 硬限制需要宿主提供可信的调用前输入计数/上界，以及能执行的输出上限；调用前预留输入和最大输出，完成后用可信实际用量结算。必须先核实真实宿主接口，不能编造计数 API。若当前路由无法满足条件，设置总 Token 硬限制时在调用前返回 TOKEN_BUDGET_UNSUPPORTED，保留检查点并提示使用调用次数限制或更换支持的路由。不能用字符估算、仅事后统计或输出上限冒充总 Token 硬限制。

未设置总 Token 硬限制时正常运行；宿主未返回用量则显示未知。费用只接受宿主可信计费数据，缺失显示未知。统计按提取、生成、修复和审查分组，包含调用次数、耗时、已知 Token、未知用量调用数；失败调用可用的计费信息也保留。

达到预算时标记 budget-paused，保存消耗、已完成证据/模块/审查及下一阶段；网页显示“预算已用完，调整后继续”。普通取消和错误保持独立状态。每个完成的模型调用之后持久化消耗，避免后续阶段失败造成统计丢失。

## 7. 接口与持久化兼容

analyze/resume 及独立模块工具增加可选模式和预算参数；补充章节使用受限枚举参数。新增人工复核和机会优先级更新能力由统一工具定义注册，网页仅调用这些已校验工具。export_report 增加 PRD/PoC 导出选项，保持原 markdown/json 行为。

新报告/检查点使用 schemaVersion 3 和 promptVersion 0.2.4；新字段均定义读取旧数据时的回退，不宣称旧报告已完成新审查。报告读取兼容 v2，旧文档显示“此版本未记录章节覆盖/审查信息”。新算法更改证据集合时清空依赖该集合的生成缓存；单纯恢复复用内容哈希和提示词版本一致的结果。

每次运行保存 document、evidence、report、checkpoint、events、审查结果、机会及用量摘要。人工记录单独维护并保留修订历史。沿用工作区目录、路径穿越防护、原子写入、沙箱写权限和网页同源检查；新增工具必须纳入写操作权限集合。

## 8. 阅读界面

沿用现有分组阅读结构。在分析入口增加研究模式和预算设置；运行中显示阶段与实际消耗。历史中预算暂停有独立状态和调整后继续操作。

报告顶部展示文本覆盖与材料边界；支持选择缺失章节补充研究。结论附近显示审查状态、理由和人工备注入口；产品机会独立成卡片，可改优先级、查看来源、下载草稿。旧报告保留可读性，不自动触发付费生成。

所有输入包括论文、模型输出和人工备注均按不可信内容处理；沿用 Markdown/SVG 清理，不执行 HTML、脚本或模型提供的操作指令。

## 9. 验收与发布

自动测试覆盖：章节识别与 unknown、优先抽样及准确覆盖、旧片段稳定性、增量研究保留历史；无效引用拒绝、跨场景高风险断言标记、假设不得升级；卡片来源、空机会、人工修订冲突、草稿导出；调用预算包含失败/修复/审查、暂停恢复、Token 能力不足时拒绝及可信能力路径硬限制；原有工具、历史软删除恢复、旧报告、图表和危险内容回退。

真实 Harness 验收使用公开论文完成：检索/导入、限定片段分析、预算暂停后继续、补充章节、审查展示、人工记录、机会与草稿导出。记录模型路由、真实调用、覆盖范围、文件位置和限制。合成模型测试与真实模型结果分别记录；Node 22/24 CI 和干净包安装均需通过。任何未通过项明确阻止相应验收声明。

版本更新至 0.2.4，更新 README、接口/配置文档、验收记录和 Release Notes，构建客户端。只提交明确相关文件，检查无私有凭据和私有验收材料。推送 main 与 v0.2.4 后运行现有 GitHub Release 工作流，核验 tgz、验收摘要及 SHA256SUMS。

npm 发布必须使用下载并核验的 GitHub Release 同一 tgz，发布后核对版本、integrity、下载包 SHA256 和干净安装。优先沿用现有已授权发布方式；自动工作流仅在现有 npm 授权能安全支持时启用，不擅自创建新的信任关系或降低 2FA。需要账号安全密钥验证时交给用户完成。同版本已存在时比较产物，不覆盖或重新打包冒充原版本。
